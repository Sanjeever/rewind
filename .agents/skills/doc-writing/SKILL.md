# 编写与维护项目文档

## 下笔前

- 确定读者、文档的主要职责、读者要完成的操作或需要作出的判断。搜索标题、旧名称、界面操作名与关键事实，检查现有章节能否承载。
- 按[贡献指南的文档维护约定](../../../CONTRIBUTING.md#文档维护)找归属。版本和默认值查配置与定义，架构约束查设计条目和实现，设备及在线结果查注明环境和基线的验收记录。

## 编写

- 每个事实设一个维护位置。优先更新权威来源，其他页面保留导航或足够完成当前步骤的摘要，并链接到原处。移动或重命名内容时更新入站链接和网站导航。
- 先核实事实，再组织文字。沿用户入口或调用边界检查实现、配置和实际执行路径。读测试时核对断言与 mock 的范围。区分当前实现、设计要求、历史观察和未确认事项。代码与设计冲突时保留证据并跟踪，避免通过改写文档把缺陷变成约定。
- 示例从实际命令和配置提取，注明工作目录、前提和预期结果。技术文档解释代码无法直接回答的操作、取舍、兼容和失败条件。

## 完稿

- 核对事实、示例、路径和章节链接。对行为、接口、配置或设计变化搜索 README、`docs/`、`website/pages/`、相关注释和示例，更新受影响的引用。
- 用 [prose-standard](../prose-standard/SKILL.md) 检查表达与事实完整性，用 [trim-cot-leakage](../trim-cot-leakage/SKILL.md) 审查正式文档。按[开发指南](../../../docs/development.md#检查与验收)选择检查，并记录未核实的部分。
